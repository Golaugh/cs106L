提到了类的话就不得不思考下类之间的关系，“继承(inheritance)” 便是经典的一个类关系。这里直接上例子：
![[Stanford_CS106L/images/7&8/8.png]]

可以看到 Shape 类作为基类拥有一个 **纯虚函数**，具体而言 virtual 表示这是一个虚函数（支持多态），const 则表示这个函数不会修改对象内部状态（即 `_radius` 或 `_width` 不会被改变），最后的 = 0 则表示其为 **纯虚函数**，没有默认实现。

基米一看到继承使用的 public 就知道还有 protected 和 private 了，在这里用一种通俗易懂的方式来区别下：
	1. 类的 private **总** 无法被派生类访问，protected **总** 无法被外界访问
	2. public 继承完整继承了基类的 public 和 protected
	3. protected 继承让基类的 public 和 protected 在派生类中都 **降格** 为 protected
	4. private 继承更进一步，在派生类中都 **降格** 为 private

如果一个派生类继承了两个类，而这两个类都继承了一个基类，那么这个派生类最终会有重复的基类的 **构造函数** ，这种情况下我们可以将中间类在继承的 public/protected/private 后面加一个 virtual 。

但是基米这时想到，如果基类是被 private 继承的是不是不加 virtual 也可以呢？毕竟派生类的派生类根本访问不了。慈祥的 GPT 笑道：

你的思考方向不错，但是实际上：

•	即便中间类是用 private 继承（例如 class B : private A {}），这并不自动避免“两个 A 子对象”的问题。继承方式（private/public/protected）并未改变“是否创建子对象”的事实。只有虚继承（virtual）才能控制“子对象是否只构造一次”的行为。
•	即使 B、C 是 private 继承 A，当 D 同时继承 B 和 C 时，如果没有虚继承，D 还是会包含两个 A 子对象。只是这些 A 子对象的访问权限可能通过 private 限制更加严格。
•	因此，若结构中存在“同个 A 被两条路径继承”的情况，仅使用 private 继承并不能解决“构造两次 A、重复子对象”这一问题。

然而依然会得到报错，想要搞清楚就得先理解在 cpp 中类在编译的时候是如何被处理的（虽然显示的是 python），具体而言类的 **数据成员** 会在内存里按照顺序依次放置，而函数会被单独放在另一个空间中：
![[14.png]]

在遇到派生类的时候，会 **接着** 基类的下面进行顺序放置：
![[15.png]]

然而在存放各种派生类的 `std::vector<Entity> entities` 中指定的是 Entity 类型，所以在运行的时候所有额外的蓝色部分都会被丢弃，这种现象称为 **对象切片 (object slicing)** 。具体而言：
	在 cpp 中，对象的拷贝／赋值如果是按值（而不是通过指针或引用），那就是把“目标类型”的对象空间分配好，然后从源对象中拷贝“目标类型那部分的数据成员”。如果源对象是派生类，目标类型是基类，那么只有基类那一部分被拷贝

所以这里实际上是先拷贝了 Entity 的数据成员，而没有给派生类的数据成员留下空间。不过解决起来也很直觉，我们通过指针来保持对象的真实类型：
```
int main() {
	Player p; Tree t; Projective b;
	std::vector<Entity*> entities = {&p, &t, &b};
	while (true) {
		for (auto& ent: entities) {
			ent->update()l
			ent->render();
		}
	}
}
```

但是一个 cpp 编译的特性让我们不得不再做些额外的处理：
	虽然 entities 内部的指针在运行时可能会指向派生类，但是在之前的编译阶段编译器就会决定调用哪个函数，而在此例其会默认指向 Entity。

所以我们需要找到一个办法在编译阶段就告诉编译器 “这个函数会被之后的派生类重写”，也就是 **动态分发 (dynamic dispatch)** 机制：
	在基类的要被重写的函数前面加上 virtual 表明其是 **虚函数** （最开头基米提到过）
	在派生类下的重载函数的函数体前面加上 override （便于阅读）

基米在想，cpp 创建者希望用户去自主决定是否使用 动态分发 ，一定是因为其会对空间与时间效率产生影响，事实也的确如此，在函数前面加上 virtual 会在内存中引入额外的 **虚指针(vpointer)** 和 **虚表(vtable)** 。
![[16.png]]

基米还在开头提到过在虚函数后面加上 = 0 来标记为 **纯虚函数** ，表示其没有内部实现必须被派生类重载，这里我们再拓展下：
	只要包含了 **至少一个** 纯虚函数 ，那么这个类就为抽象类 ，**无法被实例化**！
	只有 **完全** 重载了基类的 纯虚函数，这个派生类才可以被实例化。
