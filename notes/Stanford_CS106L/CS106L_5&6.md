在 cpp 中，所有特定的数据类型（称为容器）都在 STL (Standard Template Library) 中，而 STL 又是在前文中我们提到过的 STD 下面。大体上容器又两种类型，**序列容器 (Sequence Container)** 和 **关联容器 (Associative Container)** ，主要区别是要存放一连串独立变量还是键值对。

首先就是列表，然而其并不叫 list，而是 vector：
![[Stanford_CS106L/images/5&6/1.png]]
非常直接，唯一要注意的是 pop_back() 与 python 中的 pop() 不一样，并不能返回被删除的最后值！在细节上， Vector 使用 **动态扩容** ，在遇到超出当前容量的变量添加时，会申请一块新的为之前容量2倍的连续内存空间，然后将原来数据复制粘贴过去，最后将之前空间删除。

创建了列表后要怎么迭代呢？这里直接给结论，最上面是 **最推荐(最快)** 的方式：
```
for (const auto& elem: v) {...}
for (auto elem: v) {...}
for (size_t i=0; i < v.size(); i++) {v[i]...}
```

然而由于列表默认创建一个连续空间，并将变量从头开始放入，在某些情况下想取开头的变量非常困难，这时候就有了 **队列(deque)** ，通过 `#include <deque>` 来使用，其交互与列表基本相同，但是多出了 `push_front()` 和 `pop_front()` 。这种可以进行双向的添加删除操作得益于队列并不是用一整块空间，而是使用多个连续小空间来存储变量，并在前端与末尾也使用 **动态扩容** 技术。

map 中存储的是我们在第一回课程中学到的 pair 类型，所以在迭代的时候可以：

for (auto kv: map) {

再让我们看看这个 map 具体是怎么实现的呢？为了确保高效的键查找，cpp 使用了红黑树。很好非常简短的三个字，让本基米探探这是个什么东西：

首先我们基础的数据结构中有提到二叉查找树这个东西，即每个父节点都遵循其总大于左侧子节点，小于右侧子节点（所以 map 中的键类型需要是可比类型，即字符串，数字等等）。

然而这种感觉很高效的结构在针对单调递增或递减的数列的时候会显得十分搞笑，因为先进入的每一个值都 小于/大于 后面的值，这会使其变成单纯的一列链表。为了保证不论对于任何数列都能让树的两端都有差不多的数量同时还遵循固定的大小规则（这样搜索就可以不断均匀往下查找子节点），随后有人提出了 2-3-4 树，即并不严格遵循每个父节点只能有两个子节点，而是有以下这三种模式：
	父节点有 n 个值，并最多拥有 n+1 个子节点 （n=1，2，3）

可以在下面这张图看到，n+1 实际上是对应父节点的数值区间个数：
![[Stanford_CS106L/images/5&6/3.png]]

那么所谓的红黑树，就是设计者尝试使用“红”与“黑”的颜色标记，将这种 2-3-4 树转化成一个二叉树（即每个父节点只有最多两个子节点，同时节点最多包含一个数）。那么相对应的，对于每一种 2-3-4 树的模式，我们可以使用：
	父节点有 1 个值时，标记其为“黑”
	父节点有 2 个值时，将左侧数值标记为“黑”，右侧数值标记为“红”
	父节点有 3 个值时，中间为“黑”，两边为“红”

实际上就连基米也发现了，这种颜色标记实际上只是另一种比较的概念，对应于 2-3-4 树中不同节点的情况。当然理解起来容易实现起来难，不过大体了解一下总归是好的。
![[Stanford_CS106L/images/5&6/4.png]]

好的好的 map 就告一段落了，接下来登场的是 std::set，其与 map 的交互方式基本一模一样。
等会集合为什么会是关联容器呢？明明都是单独的独特变量打包在一起。实际上集合相当于 **没有值的 map**，并也使用红黑树存储。

关联容器最主要的作用就是进行高效的搜索，那么如果我们舍弃键的比较，能否在搜索速度上更近一步呢？这就是 `std::unordered_map` 和 `std::unordered_set` 的用武之地了。其通过 `#include <unordered_map>` 和 `#include <unordered_set>` 来进行调用。它们的交互方式与原版本近乎一样，不过在存储方式上大为不同。具体而言是在一个连续空间内使用哈希方程对不同的键进行处理然后取模，将其放在取模后对应的位置上，并在 装载参数(即固定容量下的存储个数比值)过高的时候动态扩容并重分布。

在以下的情况时通常建议使用 unordered 类型：
	空间尚有，时间紧迫
	键是不可比较类型（但是需要可哈希！）
	不知道应该使用哪种（选 unordered 就对了！）

在上面基米曾提到过
```
for (const auto& elem: v) {...}
```

是最为推荐的迭代方法，那么这个迭代中间具体发生了什么呢？我们可以想象一个抓娃娃机：
![[Stanford_CS106L/images/5&6/6.png]]

这个夹子就称为迭代器(Iterator)，负责遍历整个容器，从 .begin() 开始创建迭代器指向头元素，然后依次通过数值运算进行遍历并通过 * 进行解引用。最后指向一个空元素标记为 .end()。

细心的基米立刻注意到了示例这里的不同 —— 之前都是使用的 it++，怎么现在成了 ++it ？实际上在 cpp 中 ++it 会保持相同的引用，而 it++ 会在增加数值后返回 it 的一份 copy。或许听起来没什么大不了不就是一个数么，但是尤其是在迭代的时候我们复制的是一整个迭代器，包含各种部件，所以十分耗时。

非常神奇的是，不同的容器的迭代器功能竟然不完全一样。上面图中展示的操作是所有迭代器都具备的，接下来让我们按类别区分一下：
	首先是输入迭代器（Input Iterator），主要包含阅读元素：
		`auto elem = *it` 和 `int m = it->attribute` （当元素为 struct）
	输出迭代器（Output Iterator），主要包含写入/改写元素：
		`*it = elem` 
	顺序迭代器（Forward Iterator），按照正序进行迭代：
		`++it` 
	双向迭代器（Bidirectional Iterator）：
		`++it` & `--it` 
	随机访问迭代器（Random Access Iterator），可以跳过多个元素：
		`auto it2 = it + 5` & `auto it3 = it2 - 3` 

这个图片可以更直观的看到不同容器迭代器的能力范围，越往里的功能越全：
![[Stanford_CS106L/images/5&6/7.png]]

还有另一个老生常谈的像迭代器这样，不过是指向“万物”的东西 —— 指针。只需要在声明的变量类型后面加上 * ，然后将要赋予的变量前加上地址指示符 &，就大功告成了！
