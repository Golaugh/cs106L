```
#include <iostream>
#include <string>

int main() {
    auto str = std::make_unique<std::string>("Hello World!");

    return 0;
}
```
看起来就是一个很像 c 的结构，实际上在 cpp 文件完全可以写 c 程序（埋下伏笔），那么依次看看这些奇怪符号都有什么意义吧：
	iostream 和 string 都是 cpp 的标准库，通过 std:: 接具体方法名称来进行具体调用
	经典 int 开头，main 函数总要返回一个 0 来表示程序正确执行完毕，实际上不加也会自动补上
	这个 auto 有点像自动分配类型？是的，让编译器通过初始化表达式自动推导 str 的类型
	make_unique 是一个来自 \<memory\> 的方法，但是似乎由于其它库中包含了间接引用所以可以直接使用？先不深究，简单来说其更安全的分配了指针（第一个 slide 就有指针了难绷）
	下面的 cout 就是 cpp 输出的方法，箭头是将右侧内容插入输出流，先插入指针的解引用（str 是指向 Hello World 而不是字符串本身）获得值，然后插入 endl 进行换行和刷新

正当笔者心满意足打算干饭去的时候，突然发现这个 pow 函数我忘了加 std:: 但依然正常运行，为什么呢？物联网祖师爷，新世界奠基者，全知全能的 GPT-5 慈祥的对我说：

好问题 👍。
你发现去掉 std:: 之后，pow 仍然能正常执行，这是因为 **C++ 的标准库函数名会根据不同的头文件进入不同的命名空间**，而 cmath（以及早期的 math.h）对 pow 的处理有些特殊。
- 在 **C 语言** 中，math.h 里的函数（如 pow、sqrt）都是定义在 **全局命名空间** 里的。
- 在 **C++** 中，cmath 是 math.h 的 C++ 封装版，标准要求它把这些数学函数放到 std:: 命名空间里。
- 但是为了保持对 C 代码的兼容性（伏笔回收），大多数编译器在 \<cmath\> 里也会提供一份到全局命名空间的 **using 声明**。
